# Changelog

Version 7.1.0 adds device roles, a public query for command parameters, and
fixtures that report real device identities and can model several devices on
one gateway. It also brings current fixtures for more devices and a more
convenient CLI. No public API of 7.0.0 changes in a breaking way.

### New Features 💫
- `b8ad371` `Device.roles` holds the role strings the devices endpoint reports, such as `type:product;Vitocal_250A`, unchanged and in API order. `export_device_fixture` writes them, and `FixtureViClient` reports catalogued roles ([#214](https://github.com/ignazhabibi/vi_api_client/pull/214)).
- `b8ad371` `Device.get_command_parameters(api_feature_name, command_name)` returns the parameters of one reported command as public `CommandParameter` values with name, requirement, and constraints. A caller of `run_command` can offer valid values, such as the ventilation levels of `setLevel`. See [ADR 0006](https://github.com/ignazhabibi/vi_api_client/blob/main/docs/adr/0006-expose-reported-command-parameters.md) ([#214](https://github.com/ignazhabibi/vi_api_client/pull/214), [#215](https://github.com/ignazhabibi/vi_api_client/pull/215)).
- `b8ad371` A fixture can model several devices on one gateway. `FixtureViClient.get_devices` lists every device, device `0` first, and `scripts/add_fixture.py --device-id` adds a further device. `Vitocal200A` is the first such fixture, with its system controller and outdoor unit ([#214](https://github.com/ignazhabibi/vi_api_client/pull/214)).
- `b8ad371` New fixtures: `Vitocal250A-TwoCircuits` (`E3_Vitocal_17`), `Vitocal252A`, `Vitocal262A-T2H-R290` (`E3_Vitocal_262_02`), `Vitocal300G-CU401B` (`CU401B_G`), `Vitodens100W`, `Vitodens300W-B3HF-19` (`E3_Vitodens_300_0419`), `VitoairFs300E` (`E3_ViAir_300F_13`), and `VitochargeEvolution08` (`E3_VitoCharge_Evolution_08`). The client reference lists every fixture device with its model ID and whether it is real ([#214](https://github.com/ignazhabibi/vi_api_client/pull/214)).
- `82fc2da` The CLI help groups the shared options and ends every command's help with examples, and `vi-client --version` prints the installed version ([#216](https://github.com/ignazhabibi/vi_api_client/pull/216)).
- `82fc2da` `get-feature`, `set`, and `exec` suggest close names for a mistyped feature or API feature ([#216](https://github.com/ignazhabibi/vi_api_client/pull/216)).
- `82fc2da` `list-devices`, `list-writable`, and `exec` accept `--json`, and `list-features --filter` selects features at or below a name or matching a pattern with `*` ([#216](https://github.com/ignazhabibi/vi_api_client/pull/216)).
- `98a6fc1` `list-features --available` names the filter like the library's `only_available`; `--enabled` stays as an alias ([#215](https://github.com/ignazhabibi/vi_api_client/pull/215)).

### Other Changes ☀️
- `b8ad371` Fixtures report the model ID of the device they were exported from. `Vitocal250A` now reports `E3_Vitocal_16` instead of `Vitocal250A`, and the replaced `Vitopure350` reports `E3_VitoPure` instead of `Vitopure350`, with current features. Fixture contents are recorded API data, not a compatibility contract; fixture names stay stable within a major version ([#214](https://github.com/ignazhabibi/vi_api_client/pull/214)).
- `b8ad371` `Vitocal200A` discovers two devices. Tests that expect exactly one device per fixture need an update ([#214](https://github.com/ignazhabibi/vi_api_client/pull/214)).
- `98a6fc1` `get_features` parses through the same function as the refreshes, so a malformed response that reports one command twice for an API feature now raises `ViResponseError` there too ([#215](https://github.com/ignazhabibi/vi_api_client/pull/215)).
- `82fc2da` The `run_command` error for an unknown API feature lists close API feature names first. The CLI `get-feature` lists commands in name order ([#215](https://github.com/ignazhabibi/vi_api_client/pull/215), [#216](https://github.com/ignazhabibi/vi_api_client/pull/216)).
- `98a6fc1` Internal refactorings move value and schedule validation into `validation.py` and keep one owner lookup for features; the client reference is shorter and shows a write end to end ([#215](https://github.com/ignazhabibi/vi_api_client/pull/215)).
